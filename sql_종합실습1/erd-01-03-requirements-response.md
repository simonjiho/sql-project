## 2. 전체 답변

DBA가 정리한 학과, 학생, 교수, 교과목, 강좌, 수강의 구분은 실제 학사업무와 맞다. 현재 학사정보와 변경·승인·감사기록을 분리하는 방향에도 동의한다.

이번 실습에서는 학사업무를 지나치게 넓히기보다 다음 원칙을 우선한다.

1. 학생과 교수는 현재 소속과 현재 상태를 중심으로 관리한다.
2. 수강 취소와 성적 정정처럼 학생에게 영향을 주는 처리는 기록을 없애지 않는다.
3. 학적과 성적의 중요한 변경은 사유와 책임자를 확인할 수 있어야 한다.
4. 승인 전 변경 내용은 학생이 보는 현재 정보에 반영하지 않는다.
5. 감사기록은 현재 학사정보와 분리하여 임의 수정이나 삭제를 막는다.

## 3. 수강신청과 취소에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| ENR-Q01 | 이번 실습에서는 취소한 강좌를 다시 신청할 수 없도록 한다. 재신청이 꼭 필요한 경우에는 학사 담당자가 별도 예외 절차로 처리해야 하지만 그 절차는 이번 범위에서 제외한다. |
| ENR-Q02 | 신규 수강신청은 재학 상태인 학생만 가능하다. 휴학, 졸업, 제적 학생은 신청할 수 없다. |
| ENR-Q03 | 정원에 도달했다고 강좌 상태를 자동으로 마감으로 바꾸지는 않는다. 신청할 때 강좌가 모집 중인지와 잔여석이 있는지를 모두 확인한다. 강좌 상태는 학사 담당자가 운영 일정에 따라 변경한다. |
| ENR-Q04 | 성적이 입력된 수강 건은 바로 취소할 수 없다. 잘못 입력된 성적이라면 정정 절차로 성적을 먼저 정리한 뒤 수강을 취소한다. |
| ENR-Q05 | 성적이 입력된 강좌는 폐강할 수 없다. 성적 입력 전 폐강한 경우 신청 완료 학생은 모두 수강 취소로 바꾸고 기존 신청기록은 남긴다. 취소 사유는 폐강으로 구분한다. |
| ENR-Q06 | 마지막 자리에 여러 신청이 들어오면 먼저 정상 완료된 신청만 인정한다. 어떤 경우에도 강좌 정원을 넘겨서는 안 된다. |

신청과 취소는 날짜뿐 아니라 처리 순서를 알 수 있는 시각으로 남긴다. 취소 시각은 신청 시각보다 빠를 수 없으며 미래 시각을 임의로 입력할 수 없게 한다.

## 4. 성적과 담당 교수에 대한 답변

| GRD-Q03 | 담당 교수는 정정 사유를 남기고 본인 강좌의 성적을 정정할 수 있다. 학사 담당자가 교수 대신 예외 정정하려면 학사 책임자의 승인을 받아야 한다. 담당하지 않은 다른 교수는 성적을 입력하거나 정정할 수 없다. |

| GRD-Q05 | 이번 실습에서는 A+, A0, B+, B0, C+, C0, D+, D0, F만 사용한다. P/F, I, W와 평점 환산은 다루지 않는다. |

강좌별 성적 조회에는 현재 신청 완료 상태인 학생만 포함한다. 수강 취소 기록은 감사와 이력 확인을 위해 남기되 현재 수강 인원과 성적 명단에서는 제외한다.

## 5. 학생·교수·학과·교과목 운영에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| ORG-Q01 | 학생과 교수는 현재 소속 학과 하나만 관리한다. 전과와 소속 변경 이력은 이번 범위에서 제외한다. 다만 실제 변경 사실은 공통 변경기록에서 확인할 수 있어야 한다. |
| ORG-Q02 | 교과목은 특정 학과에 귀속하지 않고 대학 공통 교과목으로 관리한다. |
| ORG-Q03 | 교수는 소속 학과와 관계없이 다른 학과 학생이 수강하는 강좌도 담당할 수 있다. |
| ORG-Q04 | 학과 코드, 학번, 교번, 교과목 코드는 등록 후 변경하거나 다른 대상에 재사용하지 않는다. 이름과 명칭은 업무상 정정할 수 있다. |
| ORG-Q05 | 수강·성적 또는 강좌에서 사용 중인 학사정보는 삭제할 수 없다. 다른 기록에서 전혀 사용하지 않은 정보만 삭제할 수 있다. 연쇄적으로 과거 기록을 지우는 처리는 허용하지 않는다. |

학생의 학년은 학적 상태와 관계없이 마지막 학년을 1~4 중 하나로 남긴다. 학과명은 변경할 수 있지만 학과 코드는 바꾸지 않는다. 별도 폐과 상태는 이번 범위에서 관리하지 않는다.

## 6. 공식 번호와 입력 정보에 대한 답변

학교에서 사용하는 공식 번호는 다음 기준으로 정리한다.

| 정보 | 업무 기준 |
|---|---|
| 학과 코드·학번·교번·교과목 코드 | 최대 20자, 영문자·숫자·하이픈 사용 가능, 앞뒤 공백 제거, 영문자는 대문자로 통일, 중복 및 재사용 금지 |
| 분반 | 최대 10자, 영문자·숫자 사용 가능, 앞뒤 공백 제거, 영문자는 대문자로 통일 |
| 사람 이름 | 최대 100자, 필수 입력, 공백만 입력할 수 없음 |
| 학과명·교과목명 | 최대 200자, 필수 입력, 앞뒤 공백 제거 |
| 이메일 | 최대 254자, 소문자로 통일, 학생끼리 또는 교수끼리 중복 금지 |
| 전화번호 | 최대 30자, 선택 입력, 중복 허용 |

학생과 교수가 같은 이메일을 사용하는 것은 허용한다. 교과목명은 같을 수 있지만 교과목 코드는 달라야 한다. 전화번호가 없는 경우 `미등록`을 실제 정보로 저장하지 않고 조회 화면에서만 표시한다.

교수인 업무행위자는 교수 정보와 연결할 수 있게 하되, 과거 감사기록이 교수 정보의 변경이나 삭제에 영향을 받으면 안 된다.

## 8. 변경기록에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| AUD-Q01 | 한 번의 업무에서 함께 처리된 변경은 하나의 처리로 묶어 보여야 한다. 예를 들어 강좌 폐강과 학생들의 일괄 수강 취소는 같은 처리다. |
| AUD-Q02 | 대상 한 건마다 변경 전 전체 내용과 변경 후 전체 내용을 남기고, 실제로 달라진 항목도 확인할 수 있게 한다. |
| AUD-Q03 | 학사정보만 바뀌고 변경기록이 빠지는 것은 허용하지 않는다. 둘 중 하나라도 실패하면 해당 업무 전체가 취소되어야 한다. |
| AUD-Q04 | 앞뒤 공백이나 영문 대소문자를 학교 기준에 맞게 정리한 뒤 값이 같다면 실제 변경으로 보지 않는다. |
| AUD-Q05 | 현재 정보가 삭제된 뒤에도 당시 학번, 교번, 학과 코드, 교과목 코드 또는 강좌 구분정보로 과거 기록을 찾을 수 있어야 한다. |

성적은 수강에 포함된 정보로 계속 관리한다. 다만 감사 화면에서는 수강 상태 변경과 성적 변경을 구분해서 찾을 수 있어야 한다.

이름, 이메일과 전화번호도 당시 상태를 재구성하기 위해 변경 전후 내용에 포함한다. 개인정보가 포함되므로 일반 학사 담당자와 교수에게 감사기록 전체를 공개하지 않는다.

## 9. 중요 변경과 승인에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| APR-Q01 | 학사 책임자의 승인이 필요한 업무는 학사 담당자의 성적 예외 정정과 졸업·제적 상태로 들어가거나 해당 상태를 해제하는 변경이다. 재학과 휴학 사이의 변경, 강좌 상태 변경, 수강 취소는 사유를 남기되 별도 승인은 받지 않는다. |
| APR-Q02 | 승인 대상 변경은 요청 내용과 사유를 먼저 등록한다. 승인 전에는 현재 학생·수강·성적 정보에 반영하지 않는다. 승인과 실제 반영은 한 업무로 처리한다. |
| APR-Q03 | 요청자와 승인자는 같은 사람일 수 없다. 승인 시점에 학사 책임자 역할이 있는 사람만 승인하거나 반려할 수 있다. |
| APR-Q04 | 승인 대기 중 현재 정보가 달라졌다면 기존 요청은 적용하지 않는다. 오래된 요청으로 종료하고 현재 정보를 기준으로 새로 요청한다. |
| APR-Q05 | 반려, 취소 또는 오래된 요청은 수정해서 재사용하지 않는다. 기존 요청과 판단은 남기고 필요한 경우 새 요청을 등록한다. |

승인요청은 대기, 반려, 요청 취소, 오래됨, 적용 완료 상태를 구분한다. 승인 후 반영된 내용을 되돌려야 하면 기존 승인을 취소하는 대신 반대 방향의 변경을 새로 요청한다.

모든 실제 정보 변경과 삭제에는 사유를 남긴다. 신규 등록과 최초 성적 입력의 사유는 선택 사항으로 한다. 정상 처리에서 사유가 빠진 중요 변경은 없어야 한다.

## 10. 감사 조회에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| LOG-Q01 | 변경기록 검색, 한 건의 상세 열람, 자료 내보내기를 각각 한 번의 감사 조회로 기록한다. 같은 검색 결과에서 단순히 다음 페이지로 이동한 것은 별도 조회로 세지 않는다. |
| LOG-Q02 | 감사 조회에는 조회 목적을 반드시 입력한다. 조회 조건, 결과 건수, 성공 여부도 함께 남기며 실패한 조회도 기록한다. |
| LOG-Q03 | 감사 담당자와 학사 책임자만 변경요청, 승인, 변경처리 및 변경기록을 조회할 수 있다. 일반 학사 담당자와 교수에게는 감사 영역 전체 열람 권한을 주지 않는다. |

감사 조회기록 자체를 열람한 사실을 다시 감사 조회로 남기지는 않는다. 동일한 시각에 여러 변경이 있으면 업무 처리 순서대로 안정적으로 볼 수 있어야 한다.

## 11. 보존과 폐기에 대한 답변

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| RET-Q01 | 변경요청, 승인, 변경처리, 변경기록과 감사 조회기록은 각각 시스템에 기록된 시각부터 정확히 5년간 보존한다. 화면에는 한국 시간 기준으로 표시한다. |
| RET-Q02 | 성적 이의신청, 소송 또는 감사가 진행 중이면 5년이 지나도 관련 기록을 폐기하지 않는다. 해당 업무가 끝나고 보존 보류가 해제된 뒤에만 폐기를 검토한다. |
| RET-Q03 | 잘못 생성된 감사기록도 원본을 수정하거나 삭제하지 않는다. 원본을 가리키는 별도 보정 설명에 사유, 올바른 내용, 처리자와 처리 시각을 남긴다. |
| RET-Q04 | 자동 폐기는 하지 않는다. 승인된 보존 정책이 있고, 실제 폐기 건마다 학사 책임자가 대상 기간과 범위를 확인해 승인한 경우에만 수행한다. 폐기 결과도 증빙으로 남긴다. |

학사 책임자와 감사 담당자도 기존 감사기록을 직접 고칠 수 없다. DBA 수준의 물리적 변조 방지, 암호화와 전자서명은 이번 실습에서 제외한다.

| 질문 ID | 학사시스템 관리자 답변 |
|---|---|
| ARC-Q01 | 현재 학사정보는 `academic`, 변경·승인·감사정보는 `audit`으로 나누어 관리한다. 두 영역은 같은 학사관리시스템에 속하지만 열람, 변경과 보존 원칙이 다르다. |
| ARC-Q02 | 감사기록은 현재 학사정보와 독립적으로 남아야 한다. 현재 학사정보가 삭제돼도 감사기록이 사라져서는 안 되고, 감사기록 때문에 허용된 현재 정보의 삭제가 막혀서도 안 된다. |

`academic` 영역에는 학과, 학생, 교수, 교과목, 강좌와 수강의 현재 정보를 둔다. `audit` 영역에는 업무행위자와 역할, 변경요청, 승인 판단, 실제 변경처리, 대상별 변경기록, 감사 조회기록, 보정기록, 보존정책, 보존 보류와 폐기 실행 증빙을 둔다.

## 13. 조회와 실습자료 기준

- 학생은 학번 정확 검색, 이름 부분 검색, 학과·학년·학적 상태·입학 연도 조건으로 찾을 수 있어야 한다.
- 강좌의 현재 수강 인원은 신청 완료 상태인 학생만 센다.
- `미등록`, 학년별 안내 문구와 `미정`은 화면이나 조회 결과에서 계산해 표시한다.
- 학과, 학생, 교수, 교과목, 강좌 및 수강 자료는 각각 10건 이상 준비한다.
- 수강 자료에는 신청 완료와 취소 사례, 성적 자료에는 확정과 미정 사례를 모두 포함한다.
- 감사 자료에는 일반 변경, 승인 대상 변경, 반려, 오래된 요청, 폐강 일괄 취소, 삭제 후 이력 조회 및 감사 조회기록 사례를 포함한다.

## 14. 설계팀에 요청하는 결과물

위 답변을 기준으로 다음 결과물을 작성해 달라.

1. `academic`과 `audit` 영역의 경계를 표시한 ERD
2. 각 관리 대상의 업무상 의미와 식별 기준
3. 관계의 필수·선택 여부와 수량을 표시한 관계 설명
4. 중요 변경의 처리자, 사유 및 승인 여부를 정리한 표
5. 학사 변경과 변경기록이 함께 처리되는지 확인하는 시험 결과
6. 정상 처리뿐 아니라 중복 신청, 정원 초과, 무승인 변경과 감사기록 수정 시도를 막은 결과
7. 요구사항과 설계 결과가 어떻게 연결되는지 확인할 수 있는 대응표

설계 과정에서 다른 방식이 필요하면 임의로 업무 규칙을 바꾸지 말고, 변경 이유와 학사업무에 미치는 영향을 먼저 설명해 달라.
