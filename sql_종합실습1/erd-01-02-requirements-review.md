# 학사관리시스템 ERD 설계를 위한 업무 확인서

## 1. 검토 목적

학교에서 전달한 `erd-01-01-requirements.md`를 바탕으로 데이터 구조를 설계하기 전에 업무 규칙을 확인했다. 아래 질문은 기술 용어를 결정하기 위한 것이 아니라, 실제 학사 업무에서 어떤 기록을 남기고 어떤 처리를 막아야 하는지를 확인하기 위한 것이다.

답변에 따라 관리 대상, 정보의 보존 범위와 업무 관계가 달라질 수 있으므로 **필수** 항목은 ERD 확정 전에 답변이 필요하다. 표의 권장안은 DBA의 제안이며 학교의 확정 답변이 아니다.

## 2. 현재 이해한 업무 구조

DBA는 현재 요구사항을 다음과 같이 이해했다.

- 학과에는 여러 학생과 교수가 소속된다.
- 교과목은 교육 내용이고, 강좌는 해당 교과목이 특정 연도·학기·분반에 실제 개설된 수업이다.
- 교수 한 명이 강좌를 담당한다.
- 학생과 강좌의 수강 관계에는 신청 상태, 취소 시각과 최종 성적이 포함된다.
- 현재 학사정보는 `academic`, 변경·승인·감사기록은 `audit` 영역에서 관리한다.
- 변경기록은 현재 학사정보가 삭제되더라도 독립적으로 남아야 한다.

## 4. 답변 요청

학교 관리자는 각 질문에 대해 다음 내용을 중심으로 답변해 주기 바란다.

1. 현재 학사 업무에서 실제로 적용하는 기준
2. 예외가 발생했을 때 담당자가 처리하는 방식
3. 반드시 남겨야 하는 증빙과 승인 정보
4. 실습 범위에서 제외해도 되는 업무

DBA는 답변에서 확정된 업무 규칙만 ERD와 후속 설계에 반영한다. 기술적인 이유로 다른 방식이 필요하면 임의로 변경하지 않고 업무 영향과 대안을 다시 설명한다.
