# 종합실습 2 제출물 안내

## 구성

```text
submission/
├── 문항별sql/      q01.sql ~ q25.sql   (문항별 쿼리, 주석에 요구사항·기대 행 수 포함)
├── 실행출력/       q01.txt ~ q25.txt   (psql 실제 실행 출력 원본 — 쿼리 echo + 전체 결과)
├── screenshots/    문항01.png ~ 문항25.png (제출용 캡처 이미지)
└── 제출안내.md     (이 문서)
```

- 캡처 이미지는 **psql로 실제 실행한 출력**(쿼리 + 결과 + 행 수)을 그대로 렌더링한 것.
  26행을 넘는 결과 테이블은 중간을 `... (중략: N행 생략) ...`으로 표기하되
  마지막 행과 `(N개 행)` 카운트는 유지 → 전체 실행 여부를 확인 가능.
- 전체 결과가 필요하면 `실행출력/` 원본 텍스트 참조.

## 제출 방법 (강의자료 기준)

- Slack 내 댓글 제출, 기한: **3일차 과정 시작 전**
- 문항당 4점, 채점: 요구사항 반영 + 불필요한 컬럼 선택 여부
  → 모든 쿼리는 문항이 요구한 컬럼만 SELECT (`SELECT *` 미사용)

## 제출 시 언급 포인트 (같이 코멘트하면 좋은 발견 사항)

1. **enroll 데이터와 슬라이드 배경 불일치**
   슬라이드: "student_id % 3 규칙, 학생당 0~2건, 약 333명 수강 없음"
   실측: 적재 스크립트는 `%10=0 → 0건(100명), 짝수 → 2건(400명), 홀수 → 3건(500명)`.
   따라서 문항 5·18의 결과는 333명이 아닌 **100명**이며, 모든 검산은 실측 기준으로 수행함.

2. **emp 데이터와 슬라이드 배경 불일치** (문항 22)
   슬라이드: "각 직원은 매니저 10명 중 1명에게 배정" (기대 depth 1/10/300)
   실측: 적재 수식 `manager_id = 1+((gs-1)%10)` 때문에 Dev 30명이 CEO 직속으로 배정됨.
   실제 depth 분포는 **0:1 / 1:40 / 2:270**, Mgr_11은 부하 0명.
   direct_reports 쿼리는 부하 0명인 Mgr_11도 보이도록 LEFT JOIN으로 작성.

3. **문항 12 권한 이슈**
   skala_user로 `course_owner`의 FK(REFERENCES lab.emp) 생성 시
   `permission denied for table emp` 발생.
   기본 권한(SELECT/INSERT/UPDATE/DELETE)에는 REFERENCES가 포함되지 않으므로
   관리자 계정에서 `GRANT REFERENCES ON lab.emp TO skala_user;` 부여 후 성공.
